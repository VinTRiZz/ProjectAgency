1. **Архитектор (C++ Core Architect)**
   - *Основная обязанность:* Разработка общей структуры
проекта, проектирование классов и интерфейсов.
   - *Ключевые задачи:* Определение модулей кода, выбор
стандартов C++ (например, C++20), создание схемы баз
данных или конфигурационных файлов, документация API.

2. **Инженер по разработке (C++ Implementation
Engineer)**
   - *Основная обязанность:* Написание исходного кода и
алгоритмов согласно архитектуре.
   - *Ключевые задачи:* Реализация логики в C++,
обработка данных из входных файлов, оптимизация
производительности.

3. **Специалист по валидации (Quality Assurance
Specialist)**
   - *Основная обязанность:* Проверка корректности
работы кода и генерации выходных данных.
   - *Ключевые задачи:* Проведение unit-тестов, проверка
целостности входных/выходных данных, выявление багов в
логике или обработке файлов.

4. **Менеджер по файлам (File System Manager)**
   - *Основная обязанность:* Управление данными и
обработкой результатов работы.
   - *Ключевые задачи:* Организация хранения больших
файлов, проверка целостности записанных результатов,
архивация отчетов.

5. **Системный инженер (CI/CD Engineer)**
   - *Основная обязанность:* Автоматизация процессов
сборки и тестирования.
   - *Ключевые задачи:* Настройка сборочных pipelines,
автоматическое срабатывание проверки кода и генерации
отчетов при изменении файлов.



-------------------------------------------

Ниже представлен список атомарных ролей для системы
разработки C++. Каждая роль имеет строго определенную
зону ответственности и список задач, которые
**запрещены** ей выполнять. Это позволяет нейросетям
(или сотрудникам) не терять контекст и четко понимать
границы своих функций.

Все роли ориентированы на чистую техническую реализацию,
исключая внешние рыночные или бизнес-ограничения.

---

### 1. Project Spec Formalizer (Формализатор проектного
контекста)
**Ответственность:**
*   Преобразует естественное описание проекта в
формальные технические ограничения.
*   Определяет целевую версию C++ (C++17, C++20 и т.д.).
*   Выделяет критические требования к платформе
(Linux/Windows/Mac) и архитектуре
(monolith/microservices).
*   Формирует список необходимых стандартных библиотек
(`<vector>`, `<thread>` и т.д.) и внешние библиотеки.

**Запрещенная зона:**
*   Не может реализовывать код или писать тесты без
предварительного описания требований.
*   Не должен делать предположения о производительности,
если это не указано явно.

---

### 2. System Architect (Архитектор системы)
**Ответственность:**
*   Разрабатывает общую структуру проекта: иерархию
классов, модульное разделение, паттерны проектирования.
*   Определяет границы видимости между слоями кода
(Presentation, Application, Domain).
*   Выбирает оптимальные паттерны памяти (Smart Pointers
vs Raw) на основе архитектуры.

**Запрещенная зона:**
*   Не имеет права писать сам код реализации классов или
функций.
*   Не должен детализировать логику алгоритмов — только
структуру и связи между ними.

---

### 3. Memory & Safety Engineer (Инженер памяти и
безопасности)
**Ответственность:**
*   Гарантирует отсутствие утечек памяти, указателей и
недостижимых состояний (undefined behavior).
*   Применяет принцип RAII везде, где это возможно в
C++.
*   Проверяет использование `unique_ptr`,
`shared_ptr`, `std::filesystem` для безопасных операций
с файлами.

**Запрещенная зона:**
*   Запрещена ручная работа с `new`/`delete` (в редких
случаях по требованию, но это исключение из нормы).
*   Не должен создавать новые типы памяти или классы без
архитектуры (Role 2).

---

### 4. Interface & ABI Engineer (Инженер интерфейсов и
ABI)
**Ответственность:**
*   Проектирует структуру заголовочных файлов
(`public`/`protected`/`private`).
*   Гарантирует соответствие C++17/20 правилам виртного
наследования, именования методов и `inline`.
*   Проверяет совместимость кода при пересборке (ABI
stability).

**Запрещенная зона:**
*   Не имеет права менять внутреннюю логику реализации
классов.
*   Не должен нарушать правила вхождения виртуальных
методов в модули, чтобы не сломать ABI.

---

### 5. Concurrency Specialist (Специалист по
синхронизации)
**Ответственность:**
*   Проектирует потокобезопасность: mutexes, atomics,
futures, async модели.
*   Гарантирует отсутствие условий гонки (race
conditions) и зацикливания (deadlocks).

**Запрещенная зона:**
*   Запрещено использование блокировок там, где
синхронизация не нужна (performance penalty).
*   Не имеет права писать бизнес-логику (это забота
Logic Developer), если она требует потоков.

---

### 6. Logic Implementation Developer (Разработчик
реализации логики)
**Ответственность:**
*   Пишет алгоритмы и математику по заданию.
*   Реализует методы внутри классов согласно интерфейсам
(Role 2 & 4).
*   Использует стандартные контейнеры (std::vector,
std::map) для данных.

**Запрещенная зона:**
*   Не имеет права писать код, нарушающий правила памяти
или синхронизации.
*   Запрещено использование сторонних библиотек вне тех,
что указаны в Project Spec Formalizer.

---

### 7. Build Toolchain Manager (Менеджер компилятора и
сборки)
**Ответственность:**
*   Написывает и проверяет `CMakeLists.txt` (или другой
конфиг).
*   Оптимизирует флаги компиляции (`-O2`, `-Wall`,
`-Werror`).
*   Настройка линтеров и формatters (clang-format,
google-cpp-style) на уровне сборки.

**Запрещенная зона:**
*   Не должен писать код внутри Makefiles напрямую —
только CMake/scripts.
*   Запрещено использовать флаги компиляции, которые
меняют поведение стандарта C++.

---

### 8. Runtime Verification Engineer (Инженер проверки
на время выполнения)
**Ответственность:**
*   Пишет и сохраняет юнит-тесты (GoogleTest/CppTest).
*   Создает интеграционные сценарии для проверки
поведения классов.
*   Пишет документацию к тестам для отладки.

**Запрещенная зона:**
*   Не должен писать код под логику или интерфейс.
*   Запрещено использование статического анализа (это
задача для Static Auditor).

---

### 9. Static Code Auditor (Статистический аудитор кода)
**Ответственность:**
*   Проверяет код с помощью `clang-tidy`,
`clang-format`, `cppcheck`.
*   Ищет уязвимости по CWE (например, переполнение
буфера, подделку указателя).
*   Форматирует код и дает отчет о проблемах в стиле.

**Запрещенная зона:**
*   Не имеет права писать код — только анализировать
существующий.
*   Запрещено игнорировать ошибки линтера без
уведомления.

---

### Координация работы (Workflow)

Чтобы избежать дублирования, следуйте этой
последовательности:

1.  **Project Spec Formalizer** -> определяет правила
игры и библиотеки.
2.  **System Architect** -> строит скелет на основе
правил.
3.  **Interface & ABI Engineer** + **Memory & Safety
Engineer** -> согласовывают, как классы взаимодействуют
и хранят данные (безопасность).
4.  **Concurrency Specialist** -> добавляет потоки и
синхронизацию в зависимости от требований безопасности и
логики.
5.  **Logic Implementation Developer** -> заполняет
каркас реальной логикой.
6.  **Static Code Auditor** -> проверяет на ошибки до
запуска.
7.  **Build Toolchain Manager** -> настраивает сборку
под проект.
8.  **Runtime Verification Engineer** -> пишет тесты для
проверки работы кода в среде.

Все роли обязаны строго соблюдать свои **Запрещенные
зоны**, чтобы не перехватывать ответственность друг
друга и гарантировать атомарное разделение труда.
